# 技术栈复习与简历参考

整理日期：2026-09-17。依据当前本地代码，不把规划中的能力当作已实现功能。

## 项目定位

参考 DeepResearch Agent 的模块化研究流程，使用 Python 实现简化的研究型 Agent 原型。不是模型训练项目，也不是已具备实时搜索能力的生产系统。

## 技术与实际作用

| 技术 | 实际作用 | 复习要点 |

| Python / uv / venv | 模块开发和环境隔离 | 解释器、函数、类、导入、虚拟环境 |

## 关键数据流

1. `.env` 提供配置，客户端负责调用模型。
2. 规划器返回 JSON 字符串，`json.loads` 得到字典，`sub_tasks` 是列表，每个 task 是字典。
3. 调度器先并发执行两个无依赖任务，待结果完成后执行分析任务。
4. 任务原文保存在 `answer`；长答案压缩后放入 `context_answer`，短答案直接复用原文。
5. 前置任务结果和最终汇总使用 `context_answer`；报告文件保存原始子任务答案。
6. 连续入口先读历史并检索，研究成功后追加记忆；单次入口不调用记忆模块。

## 向量检索的分工

- Embedding 模型：把文字转为数字数组。
- SQLite：存取历史问题向量，避免每次重新编码；不负责相似度搜索。
- NumPy：遍历计算相似度，排序取 Top-K。
- 检索器：结合阈值与最近记录规则，将选中原文组装进提示词。
- 模型不会自动记住程序过去的请求；文件中有记忆，也要显式传入请求才可使用。

`with closing(sqlite3.connect(...)) as connection, connection:` 同时管理两件事：内层连接上下文正常退出时提交、异常时回滚；外层 closing 负责最终关闭连接。事务成功并不等于连接已关闭。

## 工具调用的分工

工具说明告诉模型有哪些能力。模型返回工具名称、参数和调用编号；注册表找到 Python 对象执行，将结果以对应 tool_call_id 回传模型。模型没有直接执行本机函数的权限。

计算器闭环已完成独立测试。当前工具循环里的模型请求仍为同步调用，即使外层函数为 async，也不能据此称为完全异步工具执行系统。尚未接入研究主流程或搜索服务。

## 简历表述参考

项目：基于 DeepSeek 的研究型 Agent 原型（个人学习项目）

技术栈：Python、OpenAI SDK、asyncio、Sentence Transformers、NumPy、SQLite。

- 参考开源研究 Agent 架构，实现结构化任务规划、依赖执行、条件摘要压缩和 Markdown 报告生成。

- 实现连续对话记忆检索，利用本地 384 维 Embedding 与余弦相似度筛选历史资料，使用 SQLite 缓存向量以减少重复编码。
- 实现可扩展工具注册表与多轮工具调用闭环，完成计算器多步运算验证。

## 建议复习顺序

配置与单次调用 → JSON 计划 → 依赖与并发 → 压缩和汇总 → 记忆文件 → 向量检索与 SQLite → 工具调用。

每个模块至少能解释：输入是什么、输出是什么、由谁调用、数据存在哪里、失败后会怎样。
